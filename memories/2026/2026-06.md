## 2026-06-04

### Codex Reconnecting 循环问题修复

**问题现象**：Codex 执行任务时不断循环 `Reconnecting... 1/5` 到 `5/5`，一直无法正常响应。

**根本原因**：WebSocket 不走代理。Codex 默认优先使用 `wss://` WebSocket 协议与 OpenAI 服务器通信，但 WebSocket 流量绕过了系统代理（叶子VPN 127.0.0.1:29448），在国内网络环境下无法直接连接 OpenAI 服务器。Codex 连续尝试 5 次 WebSocket 连接（每次约15秒超时），全部失败后才 fallback 到 HTTP/SSE 模式，浪费约75秒。

**验证**：通过代理访问 `https://api.openai.com/v1/models` 返回 403 + `unsupported_country_region_territory`，确认 OpenAI 检测到请求来源是中国大陆。

**解决方案**：修改 `C:\Users\miaoh\.codex\config.toml`，添加 HTTP-only provider 配置，强制 Codex 跳过 WebSocket，直接走 HTTP/SSE：

```toml
model_provider = "chatgpt-http"

[model_providers.chatgpt-http]
name = "ChatGPT HTTP"
base_url = "https://chatgpt.com/backend-api/codex"
wire_api = "responses"
requires_openai_auth = true
supports_websockets = false
```

关键配置：`supports_websockets = false`，强制禁用 WebSocket。

**参考**：GitHub Issues openai/codex #22634, #19821, #24045, #14297, #13041；vaitk.com 和 weste.net 相关文章。

## 2026-06-06

### Codex 又用不了的问题排查

**现象**：用户反馈 Claude Code 和 Codex 都用不了了。Claude Code 之前帮用户处理了 TUN 模式问题后 Codex 恢复了，但用户中断 Codex 进程后重启又连不上了。

**排查结果**：
- 代理出口 IP：美国洛杉矶（186.244.245.2, US）—— 节点没问题
- **关键发现**：TUN 模式已经关闭了（Get-NetAdapter 只有 WLAN 和蓝牙，没有 TUN 虚拟网卡）
- TUN 关闭后，不走代理的 curl 直接访问 `api.openai.com` 返回 `invalid_api_key`（而非 403），说明叶子VPN 的系统代理（127.0.0.1:29448）仍在接管全局流量
- `chatgpt.com` 仍返回 403 blocked —— OpenAI 对该域名的封锁比 API 域名更严格
- Codex 进程有 8 个在运行（可能是中断后残留的僵尸进程）

**根因分析**：Claude Code 帮用户开的 TUN 模式在进程中止后失效了。TUN 是虚拟网卡，需要 VPN 客户端持续运行才能维持。Codex 桌面版不走系统代理环境变量，必须靠 TUN 模式在系统层拦截所有流量才能连通。

**解决方向**：
1. 重新在叶子VPN 中开启 TUN 模式
2. 或确保 config.toml 中 `supports_websockets = false`（已配置），并确保系统代理能覆盖 Codex 的 HTTP 请求

### Claude Code 修复（最终方案）——自建 Anthropic-to-OpenAI 转换代理

**问题**：Claude Code 无法连接 API。cc-switch 代理将请求转发到 `https://api.deepseek.com/anthropic`，但该端点返回 404。

**根因**：
1. cc-switch 配置了 `apiFormat: anthropic`，直接将 Anthropic 格式请求透传到 DeepSeek 的 `/anthropic` 端点
2. DeepSeek 的 `/anthropic` 端点实际返回 404（文档说支持但实测不可用）
3. cc-switch 代理模式不稳定：启动后几秒就自动停止并恢复 settings.json 备份

**解决方案**：绕过 cc-switch，自建本地 Anthropic-to-OpenAI 转换代理：
- **代理脚本**：`C:\Users\miaoh\anthropic-proxy\proxy.py`（FastAPI + uvicorn）
- **监听端口**：127.0.0.1:15721（与 cc-switch 同端口，settings.json 无需改动）
- **功能**：将 Claude Code 的 Anthropic Messages API 请求转换为 OpenAI Chat Completions 格式，转发给 DeepSeek API
- **启动方式**：Windows 启动文件夹 `start-proxy.vbs`（开机自启）
- **settings.json**：`ANTHROPIC_BASE_URL` 设为 `http://127.0.0.1:15721`

**关键步骤**：
1. 停止 cc-switch（`taskkill /F /IM cc-switch.exe`）
2. 修改 `~/.claude/settings.json` 中 `ANTHROPIC_BASE_URL` 从 `https://api.deepseek.com/anthropic` 改为 `http://127.0.0.1:15721`
3. 部署 `C:\Users\miaoh\anthropic-proxy\proxy.py`
4. 将 `start-proxy.vbs` 放入 Windows 启动文件夹

**验证**：`claude -p "say hi"` 和 `claude -p "1+1等于几？"` 均成功返回 ✅

**注意事项**：
- cc-switch 数据库修改（providers/provider_endpoints 表）可能被重启覆盖
- 自建代理方案比 cc-switch 更稳定，完全可控

## 2026-06-12

### 网络代理残留问题诊断与修复

**问题现象**：电脑必须开VPN节点才能上网，不开节点连国内网站都访问不了，问题反复出现。

**根本原因**：
1. Clash Verge / sing-box 关闭后，系统代理 (ProxyEnable=1) 仍指向 127.0.0.1:29448，端口不通导致所有流量被卡死
2. 代理环境变量 (http_proxy/https_proxy) 也残留指向 127.0.0.1:29448
3. Clash Verge 全局模式 (mode=global) 导致国内流量也走代理

**修复措施**：
1. 即时清理：关闭系统代理 (ProxyEnable=0)，清除代理环境变量
2. 模式修改：Clash Verge 从 global 改为 rule（国内直连、国外走代理）
3. 自动监控：创建 Windows 任务计划 "ProxyGuard-代理残留监控"，每5分钟检测并自动清理
4. 一键修复脚本：`C:\Users\miaoh\Tools\fix-network-proxy.ps1`
5. 自动监控脚本：`C:\Users\miaoh\Tools\proxy-guard.ps1`
